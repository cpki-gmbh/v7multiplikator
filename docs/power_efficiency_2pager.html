Full speed.
Even on battery.

Every other CPU inference engine slows down sharply the moment Windows throttles the processor to save power. v7 keeps 94.7% of its full-power speed in power-saving mode – the average across all eight measured workloads – because nearly all of its work is moving data through memory, and a power plan barely slows memory down. llama.cpp keeps 78.7%, OpenVINO keeps 72.5% (MNN: 92.8%). So when you unplug, v7’s lead gets bigger, not smaller.

Why it works one idea: ride the bus, not the clock

token time = memory time + CPU time
On this class of laptop, the power-saving plan roughly halves the processor’s clock speed, while the memory system slows down far less. So it is mainly the CPU share of a token’s work that gets slower. If we assume the clock is halved (an assumption, not separately measured here), each engine’s measured retention implies how much of its work is clock-bound: v7’s share is about 6% – implied by its measured 94.7% retention – so there is almost nothing left for throttling to bite. llama.cpp carries roughly 27% clock-bound work (generic kernels plus thread coordination between operations) and OpenVINO about 38% (both implied the same way); halve that share, and the whole token slows down with it.

1Bandwidth-bound quantized kernels

Each generated token reads the model’s weights from memory – roughly one arithmetic step per byte read. Our hand-written AVX2 int8 kernels finish that arithmetic faster than memory can deliver the bytes, so almost no clock-sensitive work is left to slow down.

2Per-shape prefetch tuning

The engine requests data from memory before it is needed (software prefetch), with 41 tunable settings per matrix shape, adjusted automatically by the engine’s own tuner while it runs. Memory transfers stay saturated; the processor waits on delivery, never on missing data.

3Zero hot-path overhead

While generating, the engine makes no operating-system calls, takes no locks and allocates no memory on its hot path; its workers coordinate through a single shared counter. The engine’s own overhead per token is a few millionths of a second, against roughly 20 thousandths of a second spent streaming weights from memory.

4Physical-core placement

Each physical CPU core runs exactly one dedicated worker thread, pinned in place: no two threads contend for one core, and no parked, sleeping cores need waking. A few big, stable threads saturate the memory system at any clock speed.

What it is for an estimate: roughly twice the AI per charge

The mobile equation

Estimated: roughly 2x longer AI sessions per battery charge – running at the speed other engines only reach when plugged in.

An estimate built from three measured pieces: independent battery-drain tests put power-saving mode at 22–43% more battery life on everyday work; when the clock is capped, sustained computation on a 15-watt laptop chip draws roughly half the power, which means about twice the run time per charge for that kind of work (measured on clock-bound software; mihai.page, 2023); and v7 gives up only about 5% of its speed in that regime (measured), so nearly all of the extra battery time becomes generated tokens, while a clock-dependent engine pays for the same battery time with a fifth to a quarter of its speed. v7’s own energy per token has not yet been measured – a wall-meter or battery-API measurement is the planned next step.

Offline field assistant

A private, local assistant that runs for a full workday on a single laptop or tablet battery – on planes, on trains, anywhere without power or reception.

Edge & industrial

Fanless boxes, battery- or solar-backed gateways, sealed heat-limited enclosures – every power constraint bites the processor clock first. v7 is built for exactly that regime.

Always-on devices

Long AI generations without the thermal spiral: a clock-capped chip runs cool and holds its pace, and v7 keeps generating at nearly full speed the whole time.

Why this matters a feature, not an accident

Every laptop, tablet and fanless edge box throttles. Until now, running AI on battery meant choosing between speed and run time. v7’s memory-first design dissolves that trade-off: what power-saving mode takes away – the CPU clock – is what v7 depends on least. The result is an engine whose lead grows precisely in the conditions mobile devices actually face: constrained, hot, or unplugged.
