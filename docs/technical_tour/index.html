Three places an app can intervene

Choose the point that matches the change you want to make.

Before accepting a token

Scripted dialogue

Reject an unwanted token and sample again. Halt when the turn reaches a script-defined boundary.

After accepting text

Lore and document Q&A

Use SetStream to replace a draft passage or insert selected facts, then let the model continue from the edit.

As the window rolls

Long text sessions

Keep recent turns in attention. A host hook can store selected older text for later retrieval.

Speaker notes and sources

The three mechanisms have different scopes. Reject operates on the pending token and samples from existing logits. SetStream changes accepted output and can require re-forwarding. The window-displacement hook receives older text in batches, allowing application-managed memory. A model can still produce errors. Scripts define the trigger and decide what to store or change.

NATIVE KERNELS

Four prompt tokens share a weight pass

Packed QKV prefill uses the existing worker pool to process four input vectors together.

4

prompt tokens
per QKV batch

Q8 groups of 64

Each group carries an FP32 scale. Fused RMSNorm and quantization prepare the inputs.

Read each weight row once

Workers apply that row to all four inputs. A per-token path handles the remaining prompt tokens.

1.42× for the recorded packed QKV dispatch versus four separate Q8 dispatches.

Speaker notes and sources

The 1.42× figure is a dispatch microbenchmark for the documented 1024×4096 QKV shape. It is separate from end-to-end prefill and decode. The arithmetic retains group-wise FP32 scaling. The engine scatters Q, K, and V, then applies the required per-token bias and QK/RoPE operations.

Runtime tuning by matrix shape

The dispatcher splits matrix work between the caller and a pool of workers.

128

dispatch configurations
per matrix shape

Work partitioning

Each configuration defines how to split the matrix and how threads claim jobs.

Timing during inference

The tuner times alternatives during inference, tests new combinations, and saves per-shape populations for later sessions.

Speaker notes and sources

The caller takes a reserved job and may claim additional work. Worker batch sizes and chunk geometry can vary by shape. The attached assembly snapshot keeps 128 configurations per shape and records a separate active configuration index. The attached assembly snapshot interleaves A1, B1, C, B2, and A2. SELF-MODIFYING KERNELS

v7 patches prefetch instructions

A matrix shape can choose its own prefetch distances and instruction types.

41

active prefetch slots

Distance

The engine writes a new displacement to change how far ahead a prefetch reads.

Instruction type

It can swap the prefetch opcode to select a cache hint for that shape.

The previous worker batch finishes before patching. The next batch starts after the writes.

Speaker notes and sources

The dispatch cold path applies shape-dependent settings to instruction sites, then issues MFENCE and LFENCE before publishing new work. The fences order the calling thread and rely on the existing completion and single-caller contract. The patch changes prefetch hints, leaving the model arithmetic intact.

FINE-GRAINED PARALLELISM

A worker joins the sampler

The caller and a spinning worker split the vocabulary between them.

Greedy argmax

Each side finds a local maximum and its first matching index. The caller merges the two results.

Stochastic sampling

One helper stays available across temperature scaling, exponentials, and normalization.

Adaptive work split

The caller gives the faster side a little more work on the next pass. Each stochastic phase keeps its own split.

Speaker notes and sources

The assembly snapshot uses a worker continuation slot to pass registers and a target address. Greedy tie handling still selects the earlier token. In stochastic mode, separate persisted split fractions govern temperature, exponentiation, and normalization. The caller combines stage results before sampling.

STREAMING TEXT

A fixed-size attention cache

StreamingLLM keeps the first tokens and a rolling window of recent tokens.

Attention sinks

The first S cache rows stay available to attention throughout the session.

Recent context

The next W rows form a ring. Each new token replaces the oldest row once the ring fills.

FP16 rows hold the keys and values. The engine can save and reload occupied rows.

Speaker notes and sources

The budget cannot exceed the configured sequence length. A text session may continue past the cache capacity while direct attention remains limited to the retained rows. The cache uses separate FP16 key and value buffers. The online softmax updates its running normalization as it aggregates values. A SectorLogo callback can receive text displaced from the window. Cache save files carry compression and streaming metadata.

STREAM REWRITE

An edit changes model state

SetStream updates the text, token history, sampler bookkeeping, and KV cache.

Find the change

Compare old and new text, then map the first changed byte to its token.

Reuse valid state

Keep the unaffected KV prefix in a linear cache and re-evaluate the changed suffix.

Resume decoding

Sample again from the updated context. A wrapped ring needs earlier token history to rebuild valid rows.

A sidecar can revise a draft or add evidence. Rewrite cost depends on the tokens replayed.

Speaker notes and sources

Token-aligned rollback preserves the valid prefix in the ordinary case. A rewrite also brings position and presence-penalty state into agreement with the edited tokens. Once the ring wraps, the required earlier rows must be restored from live position-token history. A restored wrapped KV file can resume decoding, but the restore alone does not supply the earlier token IDs required for a rewrite.
