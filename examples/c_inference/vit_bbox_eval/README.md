# vit_bbox_eval

HF-parity bounding-box evaluation harness: synthesizes a 640x640 RGB test
image (gray background, red circle + green square) in memory, asks the VLM
to localize the shapes, and prints the model's answer.

## Run

```bat
bin\vit_bbox_eval.exe weights\databases\qwen3_vl_4b\lz4ht.db -q8 0
bin\vit_bbox_eval.exe weights\databases\qwen3_vl_4b\lz4ht.db -q8 1
```

First positional is the DB path; `-q8 <0|1>` may appear anywhere; optional
geometry overrides follow (cx cy r sqx sqy sqs). Greedy sampler. Exit code
is 0 when the model produced a non-empty answer -- there is no pass/fail on
box quality (this is an evaluation, not a unit test).

## Parity workflow

The HF reference outputs for the same synthetic images live in
`new_tools\box_test_ref\` (generated by `new_tools\box_test_ref.py`).
Compare v7's answer against the reference per model and per config (A/B/C);
the comparison protocol is documented in `docs\bounding_box_test.md` and
AGENTS.md Sec.132.
